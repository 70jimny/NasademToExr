## 1. 目的と基本仕様

NASA Earthdataから取得したNASADEM_HGT.001を、Terrain3Dが読み込める`.exr`に変換する。PowerShellから入力フォルダを指定し、**同じフォルダ**へEXRを保存する。

~~~powershell
NasademToExr.exe "D:\TerrainData\Iki"
~~~

- フォルダには`n33e129.hgt`、`n33e129.num`、`n33e129.swb`のような同名タイルの3ファイルを配置する。ZIPは事前に展開する。
- フォルダ指定だけなら、そのタイル（複数の連続タイルがある場合は結合範囲）を対象に変換する。
- 地域を限定したい場合だけ`--bounds`で**南緯側・西経側・北緯側・東経側**の境界を指定できる。フォルダ引数だけの使い方は変更しない。
- 出力は32bit FloatのRGB・OpenEXR。標高をメートル値で保持し、正規化や標高の自動補正を行わない。
- 出力の水平間隔は30m。WGS84の地理座標を**UTM（メートル単位）**に投影して格子化する。中心緯度の距離を使った近似は使用しない。

初期版ではオンライン取得、GUI、ZIPの自動展開、地形へのテクスチャ付与、水面生成、Godotの自動操作を実装しない。指定外の互換機能・自動フォールバックも実装しない。

## 3. 入力ファイル仕様

### 3.1 ファイルセット

| 拡張子 | 3601×3601のサイズ | データ | 用途 |
|---|---:|---|---|
| `.hgt` | 25,934,402 byte | Big Endian / Int16の標高（m） | 標高ラスターとして使用 |
| `.num` | 12,967,201 byte | 8bitのデータソース分類 | ファイルセット整合性の確認のみ |
| `.swb` | 12,967,201 byte | 8bitの水域分類（0＝陸、255＝水域） | ファイルセット整合性の確認のみ |

- `.hgt`の標高値はEGM96ジオイド基準。`-32768`は無効値として検出し、0mへ置換しない。
- `.num`や`.swb`の値を標高として混合しない。水面の標高補正もしない。
- 1タイルのHGTは3601×3601サンプル、角度間隔1秒角で、隣接タイルと境界サンプルが重複する。
- 拡張子は大文字小文字を区別せず認識する。セット内のベース名は一致させる。
- フォルダ直下のファイルを走査し、`hgt/num/swb`が揃ったセットを認識する。0セット、ファイル欠落、重複タイル、形式またはサイズ異常はエラーにする。

### 3.2 地理範囲と複数タイル

例：`n33e129.hgt`は**北緯33～34度、東経129～130度**の1度四方を含む。`n/s`および`e/w`と数字からタイルの緯度経度を復元する。

- GDALのSRTMHGTドライバーから地理参照情報を得る。ピクセル中心とピクセル境界の半画素差を無視しない。
- HGTの画像上方向は北、右方向は東。地理参照・向きをGDAL読込結果で確認する。
- 1セットだけなら、その地域を基本範囲とする。複数セットならGDALのVRTモザイクで連結して扱う。
- 複数タイルの境界で値を二重計上しない。同じ1秒角格子に配置し、タイル端の重複はVRTで処理する。
- `--bounds`を省略した場合、入力セットの地理的外接矩形を対象とする。入力タイルが不連続で外接矩形内に隙間があるときはエラー。
- `--bounds`を指定した場合は、指定矩形が入力タイル集合ですべて覆われることを検査する。欠落タイルがあればエラー。別地域を勝手に選ばない。
- 日付変更線または赤道をまたぐ範囲、UTMゾーンをまたぐ範囲、投影対象外の緯度域（緯度-80度未満・84度超）は初期版で扱わずエラーとする。

### 3.3 実データの確認値

`C:\Data\Download\NASADEM_壱岐島` の `n33e129.*` をWindows上で読み取った結果：

| ファイル | 確認結果 |
|---|---|
| `n33e129.hgt` | 25,934,402 byte、最小標高-25m、最大標高774m、-32768は0個 |
| `n33e129.num` | 12,967,201 byte |
| `n33e129.swb` | 12,967,201 byte |

この入力を用いた変換とTerrain3Dインポートの確認結果は第9章に記載する。

## 4. CLI仕様

### 4.1 構文・出力名

~~~powershell
# フォルダ内のタイル全域を変換する
NasademToExr.exe "D:\TerrainData\Iki"

# 緯度経度で指定した範囲を切り出して変換する
NasademToExr.exe "D:\TerrainData\Iki" --bounds "33.1,129.2,33.8,129.9"
~~~

- `--bounds`の順序は**南端緯度,西端経度,北端緯度,東端経度**。WGS84の10進度数で指定し、区切りはカンマ、少数点はピリオド（InvariantCulture）に固定。
- 引数は必須のフォルダパス1個と、任意の`--bounds`1個のみ。範囲の大小が不正なときはエラー。
- 1タイルの場合、出力は同じフォルダの`{tile}.exr`（例`n33e129.exr`）。複数タイルの場合は`nasadem.exr`。
- 出力先は必ず入力フォルダ。処理後にGodot用のプロジェクトファイル、GeoTIFF、JSONなどを恒久出力しない。
- 既存EXRが存在するときは、正常生成後に上書き。書込途中に既存の完成EXRを破損させないよう一時出力・確定置換を行う。

### 4.2 表示内容と終了コード

標準出力に、入力タイル名、`--bounds`適用の有無、採用したUTM EPSG、EXR画素数、30m間隔、標高の最小・最大、EXR保存先を表示する。UTM投影で端が切れる場合、対象地域の境界と実際の出力範囲が異なることを表示する。

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 引数／入力ファイル／空間範囲が不正 |
| 2 | 読込／再投影／EXR保存失敗 |

エラーは標準エラー出力へ原因とパスを示す。エラーログファイルやGUIは作成しない。

## 5. 地形処理の詳細

### 5.1 処理の順序

1. フォルダ内の`hgt/num/swb`セットを検査して標高タイルを識別する。
2. 必要に応じてHGTをVRTで連結し、フォルダ由来または`--bounds`の**地理的な対象範囲**を決定する。
3. 対象範囲が有効な単一UTMゾーンに入ることを確認し、WGS84（EPSG:4326）からUTMへ**GDAL/PROJで座標変換**する。
4. 投影された地形を30m格子へ双線形補間して32bit Floatの標高ラスターを得る。標高の変換倍率は1、オフセットは0。
5. 有効な格子部分だけを矩形EXRへ保存する。標高値はR/G/Bの各チャネルへ同じ値を設定する。

### 5.2 地理座標からUTMへの正確な投影

- 入力座標系：WGS84緯度経度 **EPSG:4326**。経度をX、緯度をYとして軸順序を明示して使用する。
- UTMゾーン：対象範囲の中心経度から決定。北半球は**EPSG:32601～32660**、南半球は**EPSG:32701～32760**。
- 例：`n33e129`の対象は**UTM Zone 52N（EPSG:32652）**。東京付近のUTM Zone 54Nとは異なる。
- GDAL/PROJのEPSG定義を使用して地理座標からUTMメートル座標へ変換する。中心緯度による近似計算、単純な縦横ピクセル伸縮、HGTの正方格子をそのまま30mとみなす処理は禁止。
- 標高（Y方向の値）は**EGM96基準のメートル**を保持し、楕円体高へは変換しない。処理対象は水平方向の2D座標投影だけとする。

### 5.3 切り出し、モザイク、30m格子の定義

- `--bounds`はWGS84の地理的矩形。未指定なら入力タイル全体の地理的外接矩形を使用する。
- 1度四方の地理的矩形をUTMへ投影すると、**外形は一般にUTM軸に平行な矩形にならない**。このため、地理的矩形とEXRの全画素領域が厳密に一致するわけではない。
- 初期版は**範囲外やNoDataを含むピクセルを0mで埋めない**ため、投影後の有効な地域の内側から、30m格子に整列した**面積最大の軸平行な内接矩形**を採用する。
- 実装手順：①対象の地理的矩形の境界を投影・細分化してUTMの候補外接範囲を得る、②そこへ30m単位の候補格子を置く、③各格子点を逆投影して対象地理範囲内・入力HGTのサンプル位置で補間可能かを判定する（標高値・NoDataはマスクに使用しない）、④有効／無効2値マスクに対して**最大面積の全有効矩形**を選ぶ（同面積なら上端が北、次に左端が西の順に優先）、⑤選んだ領域をEXRの出力画像とする。
- 上記は**投影による四隅の欠けを防ぐための範囲確定規則**であり、選択範囲が完全保存されるという意味ではない。対象範囲の端部は切り落とされ得る。実出力の東西南北の画素中心UTM範囲を標準出力に示す。画素の外周はその外側15mで、内接判定は画素中心と補間元サンプルに適用する。
- 重複境界は小文字タイル名の辞書順で後のタイルを採用する。VRTの`-srcnodata None`でNoDataを他タイルから補完せず、`-vrtnodata -32768`で空隙を無効値とする。データに空隙があればエラー。海域を意図的な欠損として扱わない。
- 出力画素の水平間隔はUTM上で**X＝30m、Y＝30m**。画素中心はUTMのEasting/Northingが30の整数倍となる格子に固定し、上行を北とする。仮想的なGeoTransformは`[西端中心-15,30,0,北端中心+15,0,-30]`であり、EXRには格納しない。EXRの画像サイズは入力範囲・投影条件によって算出するため、固定サイズにはしない。

### 5.4 標高の読み取りと補間

- HGTをGDAL SRTMHGTで開き、Int16標高をメートル単位のFloat32へ変換する。
- 出力各画素のUTM座標を逆投影して元の地理座標を求め、標高を双線形補間する。GDAL Warpを使用する場合は`bilinear`を明示する。
- 出力領域に含まれる入力HGTで`-32768`など無効値が検出された場合は、**エラーで中断**する。欠損を埋める、近傍値で補完する、または出力領域を欠損回避目的で縮小する処理はしない。
- 水面に対して`.swb`を用いた0mへの強制補正は行わない。
- HGTの負値は負値のまま保持する。海抜、標高、目視上の明暗に合わせた0～1正規化を行わない。
- 対象地理範囲内にあるHGTサンプルだけを切り出す。境界が1秒角格子と一致しない場合は内側のサンプルまで狭め、範囲外サンプルや未取得タイルを使わない。出力矩形内の全入力NoDataと、双線形補間で正の重みを持つ4点のNoDataを検査する。

## 6. EXRファイル仕様

| 項目 | 値 |
|---|---|
| ファイル形式 | OpenEXR、Single-Part、Scanline |
| チャネル | R / G / Bの3つ（アルファなし） |
| 型 | 各チャネルFloat32（IEEE 754） |
| チャネルの値 | R＝G＝B＝標高（m） |
| 圧縮 | ZIP（可逆） |
| 正規化 | なし。負標高・小数を保持 |
| 画素方向 | 上行が北側、右列が東側（UTM格子） |
| 水平間隔 | 30m/画素 |

例：標高125.5mは`R=125.5f`、`G=125.5f`、`B=125.5f`。NoDataを透明度や0値に変換しない。Godot/Terrain3Dが読み込むのは画像の数値であり、EXRにGIS座標を格納することは要件に含めない。

## 8. Godot Terrain3Dへのインポート

1. Godotで`addons/terrain_3d/tools/importer.tscn`を開く。
2. `Importer`の`Import File / Height File Name`に生成された`.exr`を指定する。
3. `height_scale=1`、`height_offset=0`を指定する。
4. Terrain3Dの`Mesh / Vertex Spacing=30`（m）を指定する。これにより30m格子の水平スケールを一致させる。
5. `Run Import`後に`Destination Directory`を指定し、`Save to Disk`で保存する。
6. 右が東（+X）、上が北（-Z）であることを確認する。Terrain3Dの領域端パディングはEXR範囲外として扱う。正負の高さ・向き・間隔は既知画素の数値照合、陸地・海域は描画で確認する。

## 10. 制約・留意事項

- Godotを起動せずEXRを出力する。地形の実際のGodot表示は別途確認する。
- NASADEMは概ね約30m解像度であり、補間で地形の細部が増えるわけではない。
- UTM投影によりEXRの四角形に収まらない地理的境界の端部は除外される。投影後の地形範囲は選択した緯度経度の矩形と完全には一致しない。
- 隣接タイルの欠落、標高欠損、UTMゾーン横断は**エラー**とし、別の区域選択やデータ補完への自動フォールバックを実装しない。
- HGTのEGM96鉛直基準を維持する。SWBマスクに基づく海底形状の変更は行わない。
- 入力の`.hgt`/`.num`/`.swb`と出力`.exr`はバイナリデータなので、Git管理に入れない構成とする。
- ユーザーのローカル個人利用を前提とし、認証・外部サービス連携・セキュリティ機構などの不要な追加機能は設けない。
