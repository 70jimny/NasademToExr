## 1. 目的と対象範囲

### 1.1 目的

NASA Earthdataから取得済みの `NASADEM_HGT.001` の3ファイルが入ったフォルダをPowerShellの引数で渡し、同じフォルダへ **Godot Terrain3Dがインポートできる32bit浮動小数点RGB OpenEXR（`.exr`）** を1個出力する。

基本操作は次の1コマンドとする。

```powershell
NasademToExr.exe "D:\TerrainData\Iki"
```

入力フォルダに `n33e129.hgt`、`n33e129.num`、`n33e129.swb` が存在する場合、正常終了時に `D:\TerrainData\Iki\n33e129.exr` を作成する。

### 1.2 初期版の対象

- 入力：**展開済み** NASADEM_HGT.001 の1タイル、3ファイル一式
- フォルダパス：必須の位置引数1個のみ
- 出力：同一フォルダ、入力の共通ファイル名（例：`n33e129`）を使った `.exr` 1ファイル
- 標高：HGTのメートル単位の値を保持し、浮動小数点形式へ変換
- 水平寸法：単一タイルの地理座標を概算のメートル寸法へ換算し、地形の縦横比を補正
- 操作：非対話、GUIなし。PowerShellからの実行に適する標準出力・終了コードを提供

### 1.3 初期版で実装しないもの

- NASA Earthdataへのログイン、オンライン検索、ダウンロード
- ZIPの直接読込・展開、複数タイルの結合、対象地域の部分切り出し
- WPFなどのGUI、地図プレビュー、テクスチャ・水面メッシュの生成
- SWB/NUMを使った高さの改変、品質スコアリング、補修処理
- Godotの起動、プロジェクト操作、Terrain3Dへの自動インポート
- 対応形式の拡大、旧仕様との後方互換、変換失敗時の自動フォールバック
- その他、指定されていない機能や補助ドキュメントの追加

本ツールが作成する成果物はEXR **1個** とする。処理中の一時ファイルは正常終了時に残さない。

## 3. 入力データ仕様

### 3.1 ファイル集合

| ファイル | サイズ（3601×3601の場合） | 内容 | 初期版での扱い |
|---|---:|---|---|
| `{tile}.hgt` | 25,934,402 byte | 標高。符号付き16bit整数 | **高さの入力本体** |
| `{tile}.num` | 12,967,201 byte | 標高の取得元・生成過程を示す分類値 | 共通タイル名とサイズを確認。高さ計算には使用しない |
| `{tile}.swb` | 12,967,201 byte | 水域マスク。0＝陸、255＝水域 | 共通タイル名とサイズを確認。高さ計算には使用しない |

- 1タイル当たり **3601行×3601列**。隣接タイルとは境界のサンプルが重複する。
- `.hgt`は**ビッグエンディアンのInt16**で、単位はメートル、鉛直基準は**EGM96ジオイド**。
- `.num` / `.swb`は8bit分類値で、標高値ではない。RGBの高さに誤って混ぜない。
- HGTの有効範囲はNASADEM_HGT.001の仕様では **-32767～32767**。`-32768`など範囲外の値を発見したらエラーとし、0に自動置換しない。
- ファイル拡張子は大文字小文字を区別しない。タイルの基底名は同一でなければならない。

### 3.2 ファイル名と地理範囲

入力の例：`n33e129.hgt`。

- `n`/`s`：北緯/南緯、続く2桁は南北のタイル基準緯度の絶対値。
- `e`/`w`：東経/西経、続く3桁は西側経度の絶対値。
- `n33e129`の地理的対象は、**北緯33～34度・東経129～130度**（1度四方）。
- 行0は北端、最終行は南端。列0は西端、最終列は東端。
- この規則は実際のHGTタイル座標とEarthdata Searchの検索範囲に整合していることを確認する。NASADEM利用ガイドの「northwest geographic coordinate」という表現だけを根拠に緯度方向を1度ずらさない。

対象はNASADEM_HGT.001のファイル名規則に合う1セットに限定する。該当セットが0件または2件以上ならエラーとし、先頭を暗黙選択しない。フォルダ直下の他ファイルは無視する。

### 3.3 提供された壱岐島サンプルの事実

この会話に添付された以下の実ファイルの**バイト列を解析**した結果：

| ファイル | 確認値 |
|---|---|
| `n33e129.hgt` | 25,934,402 byte、最小標高 **-25m**、最大標高 **774m** |
| `n33e129.num` | 12,967,201 byte。分類値が存在することを確認 |
| `n33e129.swb` | 12,967,201 byte。分類値 **0** と **255** のみを確認 |
| HGTの `-32768` / `-32767` | ともに0個 |

この結果は**添付サンプルの確認結果**であり、Windows実機のローカルフォルダについての検証結果ではない。

## 4. コマンドライン仕様

### 4.1 書式

```powershell
NasademToExr.exe "<展開済みNASADEMタイルのフォルダパス>"
```

具体例：

```powershell
& "D:\source\02_Windows\NasademToExr\bin\Release\net10.0\NasademToExr.exe" "D:\TerrainData\Iki"
```

開発中の実行例：

```powershell
Set-Location "D:\source\02_Windows\NasademToExr"

```

- 引数は**ディレクトリパス1つだけ**。引用符付きの日本語・空白入りWindowsパスを使用可能とする。
- 引数省略、引数2個以上、フォルダ不存在はエラー。対話入力を求めない。
- 出力名は `{tile}.exr`。例：`n33e129.exr`。
- 既存EXRは**成功時に上書き**し、失敗した処理で既存EXRを壊さないよう一時ファイルに書き終えてから置き換える。
- 実行先カレントディレクトリと入力ディレクトリを混同しない。出力先は常に入力ディレクトリ。

### 4.2 標準出力と終了コード

成功時の表示内容（例）：

```text
Input : D:\TerrainData\Iki\n33e129.hgt
Tile  : n33e129 (lat 33..34, lon 129..130)
Height: -25 .. 774 m
Output: D:\TerrainData\Iki\n33e129.exr
Pixels: 3098 x 3698
Scale : Terrain3D Vertex Spacing = 30 m
Done
```

出力画素数は第5章の計算法による**設計上の目安**であり、実装値の計算・結果を実機で照合する。

| 終了コード | 意味 |
|---|---|
| 0 | EXR書出し成功 |
| 1 | 引数・入力ファイルが不正 |
| 2 | 読取・変換・EXR書出しが失敗 |

エラーは標準エラー出力に、原因と対象パスを簡潔に表示する。詳細ログファイルや常駐プロセスは設けない。

## 5. 地形変換アルゴリズム

### 5.1 基本方針

NASAの1秒角は**緯度経度の角度間隔**である。そのため、`3601×3601`を単純に正方形のままメートル間隔でTerrain3Dに配置すると、東西方向が不自然に拡大する。

初期版は入力1タイルのみを対象とし、**WGS84楕円体のタイル中心緯度における概算距離で東西・南北の実寸を算出し、30m格子に再サンプリングする**。GDAL/PROJは導入しない。地形再現用途の近似であり、測量・GISの厳密な投影変換ではない。

### 5.2 固定パラメータ

| 項目 | 値 |
|---|---|
| 入力サイズ | 3601 × 3601 |
| 出力目標メッシュ間隔 | **30.0 m**（定数） |
| 地球楕円体 | WGS84 |
| 横方向の正方向 | 東 |
| 画像上方向 | 北 |
| 標高の倍率 | **1.0**（m→m） |
| 標高のオフセット | **0.0m** |
| 再サンプリング | **双線形補間（bilinear）** |
| 欠損標高 | 自動補完しない。入力契約違反としてエラー |

### 5.3 実寸・出力寸法

WGS84半長軸 `a=6378137.0`（m）、扁平率 `f=1/298.257223563`、第一離心率二乗 `e²=f(2-f)` とする。

タイル中心緯度 `φ`（ラジアン）での曲率半径：

```text
N = a / sqrt(1 - e² sin²φ)
M = a(1 - e²) / (1 - e² sin²φ)^(3/2)

東西の1度の距離 EW = (π / 180) N cosφ
南北の1度の距離 NS = (π / 180) M
```

目標30m間隔で、両端を含む画素数を計算する。

```text
outputWidth  = round(EW / 30.0) + 1
outputHeight = round(NS / 30.0) + 1
```

`round`は実装で**MidpointRounding.AwayFromZero**を明示する。`n33e129`の中心緯度33.5度の場合、計算上の概算は **3098×3698** ピクセル。数値計算は `double` を使用する。

出力の画素間距離と実寸は最大で端数調整による誤差を持つ。Godot側は `Vertex Spacing=30.0` に固定する。タイル中心緯度での距離換算なので、南北端まで厳密な測地的スケール一致は保証しない。

### 5.4 ピクセル補間

元のHGTの四隅が出力EXRの四隅に対応するよう、出力座標 `(x, y)` に対応する元画像の小数座標 `(sx, sy)` を求める。

```text
sx = x * (3600.0 / (outputWidth  - 1))
sy = y * (3600.0 / (outputHeight - 1))
```

周囲4サンプルから双線形補間する。

```text
ix = floor(sx), iy = floor(sy)
fx = sx - ix,  fy = sy - iy

h = (1-fx)(1-fy) * H[iy,   ix  ]
  +    fx (1-fy) * H[iy,   ix+1]
  + (1-fx)   fy  * H[iy+1, ix  ]
  +    fx    fy  * H[iy+1, ix+1]
```

端のインデックスだけ `[0,3600]` に収まるよう調整する（座標外のデータを探さないためであり、失敗時の代替処理ではない）。入力HGTは符号付き整数だが、補間結果は小数点を含む`float`に変換する。

- `-25m`などの**負の高さを維持**する。
- `.swb`の水域マスクで海面を改変しない。HGT本体の高さがそのまま基準。
- 平滑化、倍率調整、基準標高のずらし、ノイズ追加は行わない。
- 遠距離地形の見た目を改善するための人工的な高解像度生成は行わない。

## 6. EXR出力仕様

| 項目 | 指定 |
|---|---|
| ファイル形式 | OpenEXR |
| ファイル名 | `{tile}.exr` |
| 部品数 | Single Part |
| 画像形式 | Scanline |
| チャネル | **R / G / B**（3チャネル） |
| 1チャネルの型 | **FLOAT（IEEE 754 32bit）** |
| 各チャネル値 | 同じ標高値（メートル） |
| Alpha | なし |
| 圧縮 | **ZIP（可逆）** |
| 正規化 | **行わない**。値0～1への変換禁止 |
| 画像向き | 行0＝北端、列0＝西端 |

例：標高125.5mの出力ピクセルは `R=125.5f, G=125.5f, B=125.5f`。

EXRはゲーム表示用の普通の色画像ではなく、高さを格納する画像として生成する。Godot/Terrain3Dが正しいピクセル方向・標高値で読み込むことは、実機確認事項。

`TinyEXR.NET 1.2.0`の具体的なチャネル設定・書出しAPIは初回の小規模スモークテストで固定する。**OpenEXR仕様を自作してバイナリを手書きすることはしない。**

## 7. プログラム構造

1プロジェクト・単一実行ファイル相当の最小構成とする。過度な抽象化やDIコンテナは導入しない。

```text
NasademToExr/
├─ .gitignore                   # 既存
├─ NasademToExr.csproj          # コンソールアプリ設定
├─ Program.cs                   # 引数・手順・標準出力・終了コード
├─ NasademReader.cs             # 入力3ファイル検出・検査、HGT復号
├─ HeightmapConverter.cs       # WGS84概算距離・補間・画素生成
├─ ExrWriter.cs                # TinyEXR.NETでRGB FLOAT EXR保存
└─ NasademToExr_詳細設計書.md    # 本書（配置する場合）
```

- `Program.cs`：CLI引数を検査し、各処理を呼び出す。成功・失敗をPowerShellへ返す。
- `NasademReader.cs`：共通タイル名1組を解決、サイズ確認、`.hgt`をビッグエンディアンInt16として行優先で読取。入力は変更しない。
- `HeightmapConverter.cs`：第5章の計算によりメートル基準の出力画像を生成し、最小・最大標高を集計。
- `ExrWriter.cs`：RGB FLOAT/ZIPでEXRを書き込み、書込み完了後にファイルを確定させる。EXRライブラリ固有の型を他クラスへ漏らさない。

初期版は`Program.cs`からの順次処理だけで十分であり、並列化、プラグイン機構、汎用地図読込インターフェースは追加しない。

### 7.1 処理シーケンス

```text
PowerShell
  -> Program: フォルダパス
  -> NasademReader: 一意の hgt/num/swb セットを確定
  -> NasademReader: 3ファイルの長さを確認
  -> NasademReader: HGT(Int16 BE) を読込
  -> HeightmapConverter: タイル中心緯度・メートル寸法を計算
  -> HeightmapConverter: 30m格子へ双線形補間
  -> ExrWriter: RGB Float32 EXRを同フォルダへ書出し
  -> Program: 保存ファイル・画素数・標高範囲・30m設定を表示
  -> PowerShell: 終了コードを取得
```

### 7.2 入力の扱い

- ZIPの中身を直接扱わず、3ファイルが展開された**フォルダ**を受け取る。
- すべて`Path`/`Directory`/`FileStream`のUnicode対応APIで扱う。
- ファイル名は大文字小文字を無視して照合するが、出力名は既存タイル名の小文字表記（例 `n33e129.exr`）で統一する。
- 正しいファイル集合を判断できなかったときはエラーを返し、別タイルや別形式へ自動切替しない。

## 8. Godot/Terrain3D側の利用手順

EXR生成後は、Godotの **Terrain3D v1.1.0-rc1** 標準インポート機能を**手作業で**使用する。

1. Godotで `addons/terrain_3d/tools/importer.tscn` を開く。
2. `Importer` ノードのInspectorでHeight Mapに `n33e129.exr` を指定する。
3. `import_scale = 1`、`height_offset = 0` とする。
4. **Terrain3Dの `Mesh / Vertex Spacing` を `30`（m）にする**。デフォルトの1mのままでは実際より縮小して見える。
5. `Run Import` を実行し、`Data Directory`へ地形データを保存する。
6. 画像の上下反転、標高の正負、スケールが期待どおりか実機で目視確認する。

1タイルには約1度四方の標高が入るため、壱岐島の周辺海域まで含む非常に広い地形になる。初期版では島だけの切り出しは行わない。

## 10. 実装・運用上の留意点

- **標高と水域は別概念**。`swb=255`をそのままマイナス標高に変換しない。
- **負の標高は異常ではない**。海抜0mを基準にそのまま保存する。
- NASADEMの標高はEGM96基準である。Godotではゲーム世界のY値として使用し、楕円体高への変換はしない。
- メートル換算はタイル中央での局所近似。科学的な座標精度を必要とする用途には使用しない。
- 本設計は単一タイル用。複数タイルを並べて厳密につなぐ仕様は含まない。
- `.hgt`/`.num`/`.swb`/`.exr`はバイナリデータでサイズが大きいため、GitHubに誤って追加しないよう`.gitignore`の除外対象を実装時に確認する。
- 出力EXRの拡張子を単に付け替えるのではなく、実際のOpenEXR形式でシリアライズする。
- 既存実装・後方互換モードがない新規プロジェクトとして、不要な互換性維持のための分岐を追加しない。
